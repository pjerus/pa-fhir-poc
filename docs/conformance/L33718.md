## What running a second document surfaced

Adding L33718 was the generality test, and it caught two generic pipeline
defects (both fixed for all documents, with regression tests):

1. **Section-splitter false headings.** MCD PDF exports hard-wrap prose, and
   a wrapped fragment like `of 10 events and documentation of:` matched the
   heading heuristics, silently re-routing mid-policy text between section
   bodies. On L33718 this dropped the adherence requirement (≥4 h/night on
   70% of nights) from the extraction entirely. Headings must now start with
   a capital letter and name their section within the first three words
   (`src/extract/sections.ts`).
2. **Prose-harvested "covered codes".** Both policy articles' `CPT/HCPCS
   Codes` sections are literally `N/A`; the old fallback harvested
   code-shaped tokens from Coding Guidelines prose, yielding non-covered
   codes (A9279, E1399) and obsolete ones (K0554) as "covered". Covered codes
   now come only from explicit code tables, sourced from the LCD's own
   Coding Information section and unioned with the article's table when one
   exists (`src/extract/article.ts`, `src/extract/extract.ts`, `cli.ts`).

Because the fixes changed both documents' section bodies, both ground truths
(`fixtures/*.expected.json`) were re-derived by reviewing the re-extracted
requirements line-by-line against the source PDFs, and L33822 was re-reviewed,
re-approved, re-projected, and re-validated.
